# 생성 앱 작업 지침

현재 생성 범위: Compose는 표준 구성과 필수 연결만 생성합니다. 추가 통신·Service 선택과 자동 추가는 제공하지 않습니다. 기능은 필요한 파일을 복사하고 패키지·환경·DI를 수동 연결합니다. feature add는 구현 대상에서 제외합니다. 각 기능 docs의 수동 연결 안내를 따릅니다.

이 앱과 부모 Composer는 독립 저장소입니다. 작업 전 경로·저장소 루트·브랜치·stage 상태를 확인하고 사용자 변경을 보존합니다. 부모 components/를 앱 실행·빌드 시 참조하지 않습니다.

소스 이름은 camelCase, 클래스·인터페이스·컴포넌트 식별자는 PascalCase, 역할 접미사는 소문자를 사용합니다. 업무 예제·더미 클래스·최상위 models·core/composition을 만들지 않습니다. backend 흐름은 통신 → Bridge → Usecase → 필요한 Service/Repository이며 메인 di가 필요한 의존성만 주입합니다. 외부 입력은 실행 시 검증합니다.

순수 함수는 입력을 변이하지 않는 util로, 기능 Service는 class·생성자 주입으로 작성합니다. 수명 타입은 core/lifecycle/lifecycle.contract.ts를 import type으로 참조하며 수명 없는 객체에 빈 메서드를 강제하지 않습니다. 초기화 실패 시 후속 업무를 막고 역순 해제하며 원래 오류·정리 오류를 보존합니다. 공개 경계에서는 내부 경로·스택·비밀값을 숨깁니다.

DI·업무·문서는사용자 소유입니다. 필수 연결은 최초 생성 시 di.ts에 포함되며 이후 같은 파일에서 객체 생성·주입·수명 등록을 직접 수정합니다. features.manifest.ts는 생성하지 않습니다. .composer/state.json과 baseline은 최초 생성·검증 기록이며 수동 추가 기능을 자동 관리하지 않습니다. state를 직접 바꿔 검사를 우회하지 않습니다. 자동 기능 추가 명령은 구현하지 않습니다. 검증은 운영 서버와 사용자 데이터를 사용하지 않습니다. 기본 명령·폴더 역할·실제 지원 범위는 README.md를 따릅니다.

에이전트는 코드 구현과 검증 절차 문서화를 우선합니다. 단위·loopback·통합·시간 제한·전체 조합·GUI 검사는 자동 실행하지 않고 사용자가 기능을 사용할 때 직접 진행합니다. 설치·check·test·build의 작업 경로·정확한 명령·선행 조건·기대 결과를 문서로 남기고, 에이전트의 기본 확인은 짧은 문법·diff 검사로 제한합니다. 그 밖의 직접 검증은 사용자가 명시적으로 요청한 범위에서만 수행합니다. 결과를 받기 전에는 미실행·미검증으로 기록하고 검증 대기만으로 독립적인 구현을 중단하지 않습니다. 검사는 기존 사용자 데이터 대신 별도 임시 경로의 새 프로젝트에서 수행합니다.

공유·버전 관리용 설정 양식은 .env.example로 관리하고 선택한 구성의 키·설명만 보존합니다. 실제 비밀값은 넣지 않고 실행 설정으로 자동 로드하지 않습니다. 필요하면 사용자가 .env로 복사해 실제 값을 작성합니다.

실제 .env·키·토큰·캐시·node_modules·dist·release는 커밋하지 않습니다. 소스·설정·문서·테스트·.env.example·package-lock.json·.composer/state.json·.gitkeep을 보존합니다. 커밋은 요청 범위에서만 수행하며 제목은 type(scope): 한국어 요약입니다. update.md는 커밋당 한 항목을 최신순으로 기록하고 실제 검증·미검증을 구분합니다.

## 최초 생성 기준

이 앱은 Composer v0.0.0 기준으로 생성합니다. 사용자 코드·데이터·설정을 보존합니다. feature add는 구현하지 않습니다. 역추출은 실제 필요가 생겨 별도 요청한 경우에 진행합니다. 사용 중 문제 요청에 필요한 최소 검사를 수행하고 실행하지 않은 검사는 통과로 기록하지 않습니다.

추가 기능의 객체는 createDi 내부에서 지역 변수로 생성하고 필요한 Usecase·Service·Bridge 생성자에 직접 주입합니다. 수명이 필요한 객체만 같은 수명 관리자에 등록합니다. 추가 기능 때문에 di.instances를 확장하거나 업무 객체에 DI 전체를 전달하지 않습니다. 기존 필수 HTTP·IPC·window·Api의 내부 연결은 유지합니다.
